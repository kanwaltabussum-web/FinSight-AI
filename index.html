01 · INPUT

Analyze Data: what does it do?

This is the shared file-intake and results workflow. It reads a supported dataset, counts transaction rows, calculates amounts, checks invoice or transaction repeats where fields allow, flags unusual amounts, and shows the evidence returned by the analysis service.

02 · WORKSPACES

How is it different from the 12 cards?

The 12 cards are separate work areas: Finance, Accounting, Costing, Insights, Risk, Audit, Tax, Planning, Reports, AI Assistant, Standards & Compliance, and Company & Settings. Analyze Data is the shared starting point that feeds actual file findings into those relevant work areas; it is not another workspace card.

03 · FILE TYPES

Which file should I upload?

CSV/XLS/XLSX: transaction counts, totals, averages, duplicate candidates and unusual-amount checks. PDF/DOCX/PPTX/TXT: extract readable text and preview document contents. JPG/JPEG/PNG/WEBP/GIF/BMP: preview the image only; OCR is not enabled, so an image of a statement will not yet become transaction rows. Use modern .docx/.pptx files; older .doc/.ppt formats need conversion first.

How to read your results

Your file, explained clearly.

After analysis, FinSight should tell you what file was processed, how many records were read, which columns were mapped, what checks ran and which rows need review.

NormalGreen · No current rule triggered
Unusual / ReviewAmber · Check this pattern
High riskRed · Prioritize human review
Duplicate candidatePurple · Matching invoice/transaction details

Important: Duplicate and unusual are different findings. A repeated invoice/reference is a potential duplicate; an unusual transaction is a pattern that stands out. A risk flag is not proof of fraud. Duplicate results can only be reported separately when the connected analysis API returns duplicate-specific findings.
